# SlamSim

Симулятор робота для задания **«Ремонт труб»** (РРО 2026, категория «Будущие инженеры»).
Сервер на Go держит поле, проверяет каждую команду по правилам регламента и рендерит кадр камеры
робота. Код робота пишется на Python с библиотекой `rrosim`. Окно симулятора открывается в браузере.

```
┌───────────────┐   HTTP/JSON   ┌───────────────────────────┐   браузер   ┌──────────────┐
│ ваш код на    │ ────────────▶ │ slamsim (Go)              │ ──────────▶ │ окно:        │
│ Python+rrosim │ ◀──────────── │ поле, проверка команд,    │             │ поле, камера,│
└───────────────┘   события     │ датчики, камера, баллы    │             │ телеметрия   │
                    кнопки      └───────────────────────────┘             └──────────────┘
```

## Быстрый старт

1. Скачайте архив для своей системы со страницы
   [Releases](https://github.com/EndForced/SlamSim/releases/latest) и распакуйте его. Go не нужен.
2. Запустите `slamsim` (в Windows — `slamsim.exe`). Окно симулятора откроется в браузере:
   http://127.0.0.1:8080.
3. Нужен Python 3.9+. В папке архива выполните:

```bash
pip install -e python                # клиент rrosim, зависимостей нет (numpy — только для camera_array)
python python/examples/explore.py    # пример: робот едет по нажатию кнопки в окне
```

Минимальная программа:

```python
from rrosim import Sim, IllegalCommand

sim = Sim()                                    # http://127.0.0.1:8080
sim.configure(sensor_cells=[(1, 0), (1, -1), (1, 1)])

@sim.on_iteration                              # кнопка «Новая итерация» в окне
def step(sim):
    obs = sim.scan()
    sim.telemetry(front=obs.front.kind, carrying=obs.carrying)
    try:
        sim.forward()
    except IllegalCommand as e:
        sim.log(f"нельзя: {e.message}")
        sim.right()

sim.run()                                      # ждать нажатий кнопки
```

## Установка и запуск сервера

### Вариант 1: готовый релиз (рекомендуется)

Со страницы [Releases](https://github.com/EndForced/SlamSim/releases/latest) скачайте архив:

| Система | Архив |
|---|---|
| Windows | `slamsim_<версия>_windows_amd64.zip` (`windows_arm64` — для ARM-ноутбуков) |
| macOS на Apple Silicon (M1 и новее) | `slamsim_<версия>_darwin_arm64.tar.gz` |
| macOS на Intel | `slamsim_<версия>_darwin_amd64.tar.gz` |
| Linux | `slamsim_<версия>_linux_amd64.tar.gz` |
| Raspberry Pi и другие ARM | `linux_arm64` (64-битная ОС) или `linux_armv7` (32-битная) |
| Только Python-клиент, например для робота | `rrosim_<версия>_python.zip` |

В архиве лежат:
- `slamsim` — сервер; окно и картинки встроены в файл;
- `slamsim-generate` — генератор полей;
- `python/` — клиент `rrosim` с примерами;
- `data/` — сюда пишутся поля;
- `README.md`.

Распакуйте архив и запустите сервер:

```bash
./slamsim              # Linux/macOS; в Windows — двойной щелчок по slamsim.exe или slamsim.exe в консоли
```

В консоли появится `SlamSim v… запущен: http://127.0.0.1:8080`, и окно откроется в браузере.
Остановить сервер — Ctrl+C или закрыть окно консоли. Версию показывает `./slamsim -version`.

Чтобы наполнить поля (по желанию), запустите `./slamsim-generate` (`slamsim-generate.exe`) и введите
количество, например 10000. Поля дописываются в `data/pats.bin`. Если файл пуст, сервер генерирует
поле на лету при каждом сбросе, но тогда `reset(index=...)` недоступен.

macOS при первом запуске может заблокировать файл от неизвестного разработчика. Откройте его через
контекстное меню «Открыть» или снимите карантин: `xattr -d com.apple.quarantine slamsim slamsim-generate`.
В Linux/macOS, если файл не запускается, выдайте права: `chmod +x slamsim slamsim-generate`.

### Вариант 2: из исходников

Нужен Go 1.25 или новее (https://go.dev/dl/, проверка: `go version`).

```bash
git clone https://github.com/EndForced/SlamSim.git
cd SlamSim
go run ./cmd/generate                 # по желанию: наполнить data/pats.bin
go run ./cmd/slamsim                  # сервер и окно
go build -o slamsim ./cmd/slamsim     # или собрать бинарник (Windows: -o slamsim.exe)
```

### Флаги сервера

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | Адрес и порт HTTP API и окна |
| `-root` | `.` | Папка, в которой лежит (или создаётся) `data/pats.bin` |
| `-open` | `true` | Открыть окно в браузере при запуске. `-open=false` — не открывать. |
| `-version` | — | Показать версию и выйти |

```bash
./slamsim -addr 127.0.0.1:9000 -root ~/SlamSim -open=false
```

### Подключить Python

Нужен Python 3.9 или новее (проверка: `python --version`, в Linux/macOS — `python3`).
Для `camera_array()` дополнительно нужен numpy: `pip install numpy`.

```bash
pip install -e python        # из папки архива или репозитория, один раз
```

Если ставить пакет не хочется, добавьте папку в путь в начале скрипта:

```python
import sys; sys.path.insert(0, "путь/к/SlamSim/python")
```

Проверка связи:

```python
from rrosim import Sim
print(Sim().config())        # если сервер запущен, напечатается конфиг
```

### Сервер на другом компьютере

Например, симулятор работает на ноутбуке, а код робота запускается на другой машине в той же сети.

```bash
./slamsim -addr 0.0.0.0:8080            # принимать подключения со всех интерфейсов
```

```python
sim = Sim("http://192.168.1.50:8080")   # IP компьютера с сервером
```

Окно открывается с любого компьютера сети по тому же адресу. Авторизации у сервера нет, поэтому
запускайте его на `0.0.0.0` только в доверенной сети. Если подключиться не удаётся, разрешите
входящие соединения на порт в брандмауэре.

### Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `SimError: unavailable: симулятор недоступен` | Сервер не запущен или у `Sim(...)` другой адрес/порт |
| `не удалось занять 127.0.0.1:8080` при запуске | Порт занят, например вторым экземпляром. Закройте его или запустите с `-addr 127.0.0.1:9000` и `Sim("http://127.0.0.1:9000")`. |
| Окно не открылось само | Откройте адрес из консоли вручную (на сервере без графики браузер не запустить) |
| В Windows окно консоли сразу закрывается | Запустите `slamsim.exe` из `cmd`/PowerShell, чтобы увидеть ошибку |
| `reset_failed: в data/pats.bin нет полей` | Файл пуст: наполните его через `slamsim-generate` или вызывайте `reset()` без `index` |
| `satellite_disabled` | Функция режима спутника: сначала `sim.configure(satellite=True)` |
| Индикатор клиента в окне серый | Python-скрипт не дошёл до `sim.run()` или упал, смотрите консоль скрипта |
| Робот двигается медленно | Это пауза `step_delay_ms` (150 мс) для наглядности, для прогонов ставьте `sim.configure(step_delay_ms=0)` |

## Модель поля и робота

- **Поле.** Сетка 8×8 перекрёстков с шагом 280 мм. Перекрёсток `(x, y)`: x — столбец (на восток),
  y — строка (на юг). `(0, 0)` — северо-западный угол.
- **Ярусы.** Робот ездит по перекрёсткам нижнего яруса (`floor`) и по секциям верхнего (`section`).
  Подняться или спуститься можно только по пандусу (`ramp`), вдоль его подъёма. Проезд по пандусу
  считается за 3 секции.
- **Перемещение.** Робот стоит на перекрёстке и смотрит на север, юг, восток или запад.
  `forward`/`backward` — на одну клетку, `left`/`right` — поворот на 90° на месте.
- **Трубы.** Две трубы стоят на нижнем ярусе, одна — на секции верхнего, все на белых подставках.
  Трубу снимают с соседнего перекрёстка того же яруса, подъехав **поперёк** трубы.
  После снятия белая подставка остаётся на поле и по-прежнему мешает проезду.
- **Зелёные подставки.** Три в ряд у границы поля. Трубу кладут с перекрёстка прямо перед подставкой,
  лицом к границе.
- **Баллы** считаются по п. 8.3: 2 за каждую снятую трубу, 6 за каждую уложенную, 6 за правильный
  порядок цветов (синяя между красными или красная между синими), 25 за эффективную логистику.
- **Логистика.** Секции считаются с момента, когда робот снял первую трубу. Повороты не считаются.
  Баллы за логистику даются, если все три трубы уложены и секций не больше эталона.
  Эталон — минимальная сумма для перевозки по одной трубе (п. 3.2). Его считает генератор полей.
- **Режимы.** В режиме **хардкор** (SLAM, по умолчанию) робот знает только показания датчиков и кадр
  своей камеры. В режиме **спутника** (`satellite=True`) доступны абсолютная поза, карта целиком
  и камера над полем, как в финальном туре.

## Библиотека rrosim

### Sim

```python
Sim(url="http://127.0.0.1:8080", timeout=70)
```

Клиент одного сервера. Все методы синхронные. Методы робота возвращают `Observation` с состоянием
после команды. Нелегальная команда бросает `IllegalCommand`, а состояние поля не меняется.

### Настройки

```python
sim.configure(sensor_cells=None, satellite=None, capacity=None, step_delay_ms=None,
              camera=None, lighting=None, scene=None) -> dict
```

Меняются только переданные параметры, остальные остаются как были. Вложенные словари
(`camera`, `lighting`, `scene`) сливаются с текущими по полям, кроме списка `lighting["lights"]` —
он заменяется целиком. Метод возвращает полный конфиг. Неверное значение бросает `SimError`
с кодом `bad_config`.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `sensor_cells` | `[(1,0),(2,0),(1,-1),(1,1),(0,-1),(0,1)]` | Клетки, которые видит робот: `(вперёд, вправо)` от робота. `(1,0)` — перед роботом, `(0,-1)` — слева, `(-1,0)` — сзади. До 64 клеток, смещение до ±8. |
| `satellite` | `False` | Режим спутника: поза в ответах, `map()`, `reference()`, `camera("satellite")`. |
| `capacity` | `1` | Сколько труб робот везёт одновременно (1–3). |
| `step_delay_ms` | `150` | Пауза после каждой команды, чтобы движение было видно в окне (0–5000). Для быстрых прогонов ставьте 0. |
| `camera` | см. [Камера](#камера-и-освещение) | Положение и параметры камеры робота. |
| `lighting` | один источник над центром | Источники света. |
| `scene` | `stand_height=60, holder_height=60` | Высота низа трубы над поверхностью на белой и зелёной подставке, мм (10–300). |

```python
sim.config() -> dict                               # текущий конфиг
sim.reset(index=None, same=False) -> Observation   # новое поле
```

`reset()` загружает случайное поле из `data/pats.bin`. Если файл пуст, поле генерируется на лету.
`index` выбирает конкретное поле из файла, `same=True` перезапускает текущее с начальной позиции.
При сбросе обнуляются баллы, секции и таймер.

Примеры:

```python
from rrosim import Sim

sim = Sim()

# датчики: клетка впереди, две впереди, впереди-слева/справа; хардкор; быстрые команды
cfg = sim.configure(sensor_cells=[(1, 0), (2, 0), (1, -1), (1, 1)],
                    satellite=False, step_delay_ms=0)
print(cfg["sensor_cells"])

# поменять только одно поле камеры, остальные настройки сохранятся
sim.configure(camera={"pitch": -45})
print(sim.config()["camera"])

obs = sim.reset()            # случайное поле
obs = sim.reset(index=12)    # поле №12 из data/pats.bin (файл должен быть наполнен, см. cmd/generate)
obs = sim.reset(same=True)   # заново то же поле
print(obs.front, obs.score["total"])
```

### Команды робота

| Метод | Что делает | Типичные ошибки |
|---|---|---|
| `forward()` | На клетку вперёд | `out_of_field`, `blocked`, `no_passage` |
| `backward()` | На клетку назад, не поворачиваясь | то же |
| `left()`, `right()` | Поворот на 90° на месте | — |
| `pick()` | Снять трубу прямо перед роботом | `no_tube`, `wrong_approach`, `capacity` |
| `place(color=None)` | Положить трубу на зелёную подставку перед роботом. `color="red"`/`"blue"` выбирает трубу, если робот везёт несколько. По умолчанию кладётся последняя взятая. | `no_holder`, `wrong_approach`, `holder_busy`, `empty`, `no_such_color` |
| `scan()` | Показания датчиков без движения | — |

Все методы возвращают `Observation`.

Примеры:

```python
from rrosim import IllegalCommand

obs = sim.forward()
print(obs.sections, obs.front.kind)

sim.left(); sim.left()          # разворот на 180°
try:
    sim.backward()              # шаг назад без поворота
except IllegalCommand as e:
    print("сзади не проехать:", e.code)

# объехать препятствие: пробовать вперёд, иначе поворачивать направо
for _ in range(4):
    try:
        sim.forward()
        break
    except IllegalCommand as e:
        print("не проехал:", e.code)   # blocked / no_passage / out_of_field
        sim.right()

# снять трубу перед роботом
try:
    sim.pick()
except IllegalCommand as e:
    if e.code == "wrong_approach":
        print("подъехать поперёк трубы")
    else:
        print("трубы нет:", e.code)    # no_tube, capacity

# положить на зелёную подставку перед роботом (последнюю взятую трубу)
try:
    obs = sim.place()
    print(obs.score)                   # {"total": ..., "finished": ...}
except IllegalCommand as e:
    print("не положил:", e.code)       # no_holder, empty, holder_busy, wrong_approach

# при capacity > 1 можно выбрать цвет: sim.configure(capacity=2), затем sim.place(color="blue")
```

### Датчики: Observation и Cell

```python
obs = sim.forward()
obs.scan          # list[Cell] — по одной на каждую клетку из sensor_cells, в том же порядке
obs.front         # Cell для (1, 0) или None, если её нет в sensor_cells
obs.at(f, r)      # Cell по смещению или None
obs.carrying      # ["red", ...] — трубы на роботе
obs.sections      # пройдено секций с первого касания трубы
obs.score         # {"picked", "placed", "pick_points", "place_points", "bonus",
                  #  "logistics", "total", "finished"}
obs.pose          # {"x", "y", "heading"} — только в режиме спутника, иначе None
obs.raw           # исходный JSON ответа
```

Поля `Cell` (все направления — в системе координат робота):

| Поле | Значения |
|---|---|
| `f`, `r` | Смещение вперёд и вправо |
| `kind` | `out` (за полем), `floor`, `section`, `ramp`, `tube` (труба на белой подставке), `stand` (белая подставка без трубы), `holder` (зелёная подставка) |
| `level` | `1` — нижний ярус, `2` — верхний (для `floor`, `section`, `tube`, `stand`, `holder`) |
| `color` | `red`/`blue`: цвет трубы или трубы на зелёной подставке; `None`, если подставка пуста |
| `ramp_up` | Для пандуса: куда он поднимается — `forward`, `backward`, `left`, `right` |
| `tube_axis` | Для трубы: `across` — при текущем курсе робот стоит к ней поперёк и может её снять, если она прямо перед ним; `along` — нужно подъехать с другой стороны |
| `id` | Сырой ID клетки модели `matrixfactory`, только в режиме спутника |

Примеры:

```python
obs = sim.scan()

# проверить, можно ли снять трубу
f = obs.front
if f and f.kind == "tube" and f.tube_axis == "across":
    sim.pick()

# заехать на пандус, если он впереди и поднимается вперёд
if f and f.kind == "ramp" and f.ramp_up == "forward":
    try:
        sim.forward()
    except IllegalCommand as e:
        print("на пандус не заехать:", e.message)

# перебрать все клетки датчиков
for c in obs.scan:
    print(f"({c.f:+d},{c.r:+d}) {c.kind:8} ярус={c.level} цвет={c.color}")

left = obs.at(1, -1)            # клетка впереди-слева
print(left.kind if left else "нет такого датчика")
```

Только в режиме спутника:

```python
sim.map()        # {"cells": 8×8 Cell, "pose": {...}} — абсолютная карта, строки сверху вниз (с севера на юг)
sim.reference()  # {"route": [[клетки], ...6 отрезков], "sections": эталон} — для отладки
```

Пример: найти все трубы на карте и узнать эталон.

```python
sim.configure(satellite=True)
m = sim.map()
print("робот:", m["pose"])
for y, row in enumerate(m["cells"]):
    for x, c in enumerate(row):
        if c["kind"] == "tube":
            print(f"труба {c['color']} на ({x}, {y}), ярус {c['level']}")
print("эталон:", sim.reference()["sections"], "секций")
```

Номер клетки в маршруте `reference()["route"]` — это `y * 8 + x`. Полный пример проезда по
эталону — в `python/examples/follow_reference.py`.

### Камера и освещение

```python
sim.camera(view="robot", size=None, name=None) -> bytes             # PNG
sim.camera_array(view="robot", size=None, name=None) -> np.ndarray  # H×W×3, uint8, RGB (нужен numpy)
sim.save_camera(path, view="robot", size=None, name=None)
```

`view="robot"` — камера робота: основная или именованная (`name`, см.
[Несколько камер](#несколько-камер)). `view="satellite"` — камера в 2,8 м над центром поля с обзором 95°
(п. 7), квадратный кадр стороной `size` (по умолчанию 480), только при `satellite=True`.
Кадр рендерится на сервере трассировкой лучей. Кадр 320×240 со сглаживанием 2×2 занимает около 30 мс
на 4 ядрах.

Параметры `camera`:

| Поле | По умолчанию | Описание |
|---|---|---|
| `x`, `y`, `z` | `80, 0, 200` | Смещение камеры в мм от центра клетки робота: вперёд, вправо, вверх от поверхности, на которой стоит робот. x, y: ±500; z: 0–1000. |
| `pitch` | `-30` | Угол оптической оси к плоскости поля, градусы. Отрицательный — вниз, `-90` — строго вниз. |
| `yaw` | `0` | Поворот вокруг вертикали относительно курса робота. Положительный — вправо. |
| `roll` | `0` | Поворот вокруг оптической оси. |
| `fov` | `70` | Горизонтальный угол обзора, 5–170°. Вертикальный определяется соотношением сторон. |
| `width`, `height` | `320, 240` | Размер кадра, 8–1920. |
| `aa` | `2` | Сглаживание: `aa×aa` лучей на пиксель (1–4). Время растёт как `aa²`. |
| `noise` | `0` | СКО гауссова шума, доля полной яркости (0–1). Например, `0.02`. |
| `k1` | `0` | Радиальная дисторсия: `<0` — бочка, `>0` — подушка (−1…1). |

На пандусе камера наклоняется вместе с роботом (уклон 100/300). Корпус робота в кадре не рисуется.

Параметры `lighting`:

| Поле | По умолчанию | Описание |
|---|---|---|
| `ambient` | `0.35` | Рассеянный свет (0–2). |
| `lights` | `[{"x": 980, "y": 980, "z": 2500, "intensity": 0.75}]` | До 8 точечных источников. `intensity` 0–5, `z > 0`. |
| `shadows` | `True` | Тени от источников. |
| `specular` | `1` | Множитель бликов (0 — всё матовое). Блики заметнее всего на чёрной плёнке и трубах. |

**Координаты источников света** — в мм в системе поля: x на восток, y на юг, z вверх.
`(0, 0)` — центр северо-западного перекрёстка, перекрёсток `(col, row)` находится в
`(280·col, 280·row)`, центр поля — `(980, 980)`. Затухания света с расстоянием нет.

```python
sim.configure(
    camera={"x": 60, "z": 180, "pitch": -35, "fov": 80, "noise": 0.02, "k1": -0.1},
    lighting={"ambient": 0.3, "lights": [
        {"x": -300, "y": 980, "z": 600, "intensity": 1.0},    # низкий свет с запада — длинные тени
        {"x": 1960, "y": 0, "z": 2500, "intensity": 0.4},
    ]},
)
frame = sim.camera_array()        # дальше — OpenCV, свой детектор и т.п.
```

Ещё примеры:

```python
sim.save_camera("robot.png")                       # кадр камеры робота в файл
png = sim.camera()                                 # те же байты PNG в памяти

sim.configure(satellite=True)
sim.save_camera("top.png", view="satellite", size=800)   # вид сверху 800×800

# доля красных пикселей в кадре — например, чтобы заметить красную трубу или границу
import numpy as np
f = sim.camera_array().astype(int)
red = (f[..., 0] > 150) & (f[..., 1] < 80) & (f[..., 2] < 80)
print(f"красного: {red.mean():.1%}")

# камера смотрит строго вниз — удобно для следования по линии
sim.configure(camera={"x": 0, "y": 0, "z": 150, "pitch": -90, "fov": 60, "width": 160, "height": 120})
```

Геометрия сцены взята из п. 15:
- баннер 2440 мм, линии 20 мм, красная граница 80 мм вокруг баннера;
- секции и пандусы 300×300×100: чёрная плёнка, белые линии 20 мм, на пандусе круги Ø80 (если смотреть на подъём, красный слева, синий справа);
- трубы Ø50×250 цветов RAL 3028 и RAL 5015 на белых подставках;
- зелёные подставки стоят поперёк чёрной линии вплотную к красной границе (п. 2.3).

Допущения: отступ сетки от края баннера — 240 мм с каждой стороны; соседние секции по 300 мм
перекрываются на 20 мм, потому что шаг сетки 280 мм. Высоты подставок в регламенте не указаны,
они задаются через `scene`.

### Несколько камер

Кроме основной камеры (`main`, настраивается через `camera`), у робота может быть до 8 именованных
камер: например, передняя, задняя, боковые и камера вниз для линии. У каждой свои положение, углы,
обзор, размер кадра и эффекты.

```python
front = sim.get_camera()                          # основная камера "main"
rear  = sim.add_camera("rear", yaw=180)           # смотрит назад
left  = sim.add_camera("left", yaw=-90, fov=90, width=160, height=120)
line  = sim.add_camera("line", x=60, z=120, pitch=-90, fov=60, width=160, height=120)

frames = {c.name: c.array() for c in (front, rear, left, line)}   # numpy-кадры всех камер
rear.save("rear.png")
png = left.frame()                                # PNG-байты

left.configure(pitch=-60)                         # меняются только переданные поля
print(left.config())                              # текущие настройки этой камеры
print(sim.cameras())                              # {"main": {...}, "rear": {...}, ...}

line.remove()                                     # или sim.remove_camera("line")
```

| Метод | Описание |
|---|---|
| `sim.add_camera(name, **params) -> Camera` | Добавить камеру. Поля, которые не переданы, берутся из настроек по умолчанию. Если камера уже есть, меняются только переданные поля. Имя: латиница, цифры, `_` и `-`, до 32 символов, не `main`. |
| `sim.get_camera(name="main") -> Camera` | Объект существующей камеры; если её нет — `SimError("unknown_camera")` |
| `sim.remove_camera(name)` | Удалить камеру (основную удалить нельзя) |
| `sim.cameras() -> dict` | Настройки всех камер, включая `main` |
| `Camera.frame()`, `.array()`, `.save(path)` | Кадр этой камеры: PNG, numpy, файл |
| `Camera.configure(**params)`, `.config()` | Изменить или прочитать настройки этой камеры |
| `Camera.remove()` | Удалить камеру |

`Camera` — лёгкий объект: он хранит только имя, а настройки живут на сервере. Несколько объектов
с одним именем управляют одной и той же камерой, а камеры, добавленные из одного скрипта, видны
в другом. Без объектов то же самое делается через `sim.camera(name="rear")`,
`sim.camera_array(name="rear")` и `sim.configure(cameras={"rear": {...}, "old": None})`
(`None` удаляет камеру).

Каждый кадр рендерится отдельным запросом, поэтому кадры с N камер стоят примерно в N раз дороже.
Для частых кадров уменьшайте `width`/`height` и `aa`. Пока между запросами не было команд,
все камеры снимают одно и то же состояние поля.

В окне симулятора камера выбирается из выпадающего списка рядом с «робот», или адресом
`http://127.0.0.1:8080/#camera=rear`.

### Телеметрия

```python
sim.telemetry(state="ищу трубу", target=(3, 4), battery=11.8)   # таблица «ключ — значение» в окне
sim.telemetry(_clear=True, state="старт")                       # сначала очистить таблицу
sim.log("взял красную трубу")                                    # строка в журнал окна
```

Значения должны сериализоваться в JSON: числа, строки, списки, словари. Ключ, который уже есть
в таблице, обновляется на месте.

### Кнопка «Новая итерация»

```python
@sim.on_iteration
def step(sim): ...      # вызывается при каждом нажатии кнопки в окне

sim.run()               # блокирует; Ctrl+C — выход
```

`run()` ждёт событий от сервера (long-poll по 25 с). Если обработчик бросил исключение, traceback
печатается в консоль, ошибка пишется в журнал окна, и клиент ждёт следующего нажатия. Нажатия,
пришедшие во время работы обработчика, копятся в очереди (до 16). Пока клиент ждёт, в окне горит
зелёный индикатор «Python-клиент ждёт итерацию».

`on_iteration` можно вызвать и как обычную функцию: `sim.on_iteration(step)`.

Пример: каждое нажатие — один цикл «скан, решение, движение», с телеметрией.

```python
from rrosim import Sim, IllegalCommand

sim = Sim()
sim.configure(step_delay_ms=150)
sim.telemetry(_clear=True)
steps = 0

@sim.on_iteration
def step(sim):
    global steps
    steps += 1
    obs = sim.scan()
    sim.telemetry(step=steps, front=obs.front.kind, carrying=obs.carrying, score=obs.score["total"])
    try:
        sim.forward()
    except IllegalCommand as e:
        sim.log(f"шаг {steps}: {e.message}")
        sim.right()

sim.run()
```

### Ошибки

```python
from rrosim import SimError, IllegalCommand   # IllegalCommand — подкласс SimError

try:
    sim.forward()
except IllegalCommand as e:
    print(e.code, e.message)
```

`IllegalCommand` — нелегальная команда робота, состояние не изменилось:

| Код | Когда |
|---|---|
| `out_of_field` | Клетка за краем поля |
| `blocked` | В клетке труба, белая или зелёная подставка |
| `no_passage` | Нет проезда: другой ярус без пандуса, въезд на пандус сбоку и т.п. |
| `no_tube` | `pick()`, а перед роботом нет трубы |
| `wrong_approach` | К трубе подъехали вдоль или с другого яруса; к зелёной подставке — не спереди |
| `capacity` | Робот уже везёт `capacity` труб |
| `no_holder` | `place()`, а перед роботом нет зелёной подставки |
| `holder_busy` | На подставке уже лежит труба |
| `empty` | `place()`, а робот ничего не везёт |
| `no_such_color` | `place(color)`, а трубы такого цвета на роботе нет |
| `unknown_command` | Неизвестная команда (только при прямых HTTP-запросах) |

`SimError` — остальные ошибки:
- `unavailable` — сервер не запущен;
- `bad_config` — неверная настройка;
- `satellite_disabled` — функция режима спутника вызвана без `satellite=True`;
- `reset_failed` — нет поля с таким номером;
- `unknown_camera` — нет камеры с таким именем;
- `bad_json`, `bad_view`.

## Окно симулятора

`http://127.0.0.1:8080`. Окно показывает истинное состояние, в том числе то, чего робот не видит.

- **Поле** с роботом, жёлтыми рамками на клетках датчиков и трубами, которые везёт робот.
  Флажок «эталон» рисует эталонный маршрут.
- **Кнопки:**
  - «Новая итерация (скан + проезд)» вызывает обработчик `on_iteration`;
  - «Новое поле» загружает случайное поле;
  - «Перезапуск» начинает текущее поле заново.
- **Камера:** выкл, робот или спутник. Кадр обновляется, когда что-то изменилось.
  Вид можно задать адресом: `http://127.0.0.1:8080/#camera=robot`.
- **Заезд:** номер поля, время, поза, что везёт робот, секции и эталон, баллы, режим, датчики,
  камера, свет.
- **Телеметрия клиента и журнал**: команды взятия и укладки, ошибки, сообщения из `sim.log()`.
- **Ручное управление:** `↑`/`↓` — вперёд/назад, `←`/`→` — поворот, `P` — взять трубу,
  `O` — положить. Команды проверяются так же, как из Python.

## HTTP API

Библиотека — тонкая обёртка над этим API, его можно вызывать из любого языка. Тела запросов
и ответов — JSON. Ошибка возвращает HTTP 400 с телом `{"error": "<код>", "message": "<текст>"}`.

| Метод и путь | Тело или параметры | Ответ |
|---|---|---|
| `POST /api/cmd` | `{"cmd": "forward\|backward\|left\|right\|pick\|place", "color"?: "red\|blue"}` | observation |
| `GET /api/scan` | — | observation |
| `POST /api/reset` | `{"index"?: int, "same"?: bool}` | observation |
| `GET /api/config` | — | конфиг |
| `POST /api/config` | частичный конфиг (поля как в `configure`); `cameras` сливается по камерам, `null` удаляет камеру | конфиг |
| `GET /api/camera` | `view=robot\|satellite`, `name` (камера робота, по умолчанию `main`), `format=png\|raw`, `size` (для спутника) | PNG или RGB-байты построчно; размеры в заголовках `X-Width`, `X-Height` |
| `POST /api/telemetry` | `{"data"?: {...}, "log"?: str, "clear"?: bool}` | `{"ok": true}` |
| `GET /api/events` | `timeout` — секунды, 0–60 | `{"events": ["iteration", ...]}` (пусто по таймауту) |
| `POST /api/iterate` | — | нажатие кнопки «Новая итерация» |
| `GET /api/map` | только в режиме спутника | `{"cells", "pose"}` |
| `GET /api/debug/reference` | только в режиме спутника | `{"route", "sections"}` |
| `GET /api/state` | — | полное состояние для окна (истинная поза, клетки, телеметрия, журнал) |

Формат observation:

```json
{"ok": true, "scan": [{"f": 1, "r": 0, "kind": "floor", "level": 1}],
 "carrying": [], "sections": 0, "score": {"total": 0, "...": 0}, "pose": {"x": 3, "y": 2, "heading": "north"}}
```

Поле `pose` есть только в режиме спутника.

## Поля и генератор

Поля хранятся в `data/pats.bin`: 144 байта на поле — матрица 8×8 и эталонный маршрут. Наполнить файл:

```bash
./slamsim-generate        # из релиза; из исходников — go run ./cmd/generate
                          # спросит количество; 100 000 полей — несколько секунд
```

Генератор `fastgen` соблюдает правила жеребьёвки:
- 11 паттернов (10 пандусов, 20 секций) в случайных местах и направлениях;
- три зелёные подставки у границы, перед ними два свободных ряда;
- две трубы на нижнем ярусе и одна на верхнем, с перекрёстком между трубой и пандусом;
- задача проверяется на решаемость, для каждого поля считается эталонный маршрут.

Если файл пуст, симулятор генерирует поле на лету.
